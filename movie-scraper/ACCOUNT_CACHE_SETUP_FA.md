# راه‌اندازی دیتابیس و حساب کاربری CineSense

## وضعیت فعلی
کد پیاده‌سازی شده و تست‌های MySQL 8 با دیتابیس موقت CI اجرا می‌شوند، اما **بدون اتصال یک دیتابیس واقعی و ایمیل فرستنده، در سایت لایو حساب کاربری و کش ۲۰روزه فعال نمی‌شوند**. این محدودیت عمداً fail-safe است؛ نسخه فعلی جست‌وجو و تحلیل فیلم همچنان کار می‌کند.

## ۱. دیتابیس MySQL 8+ مدیریت‌شده
یک MySQL 8+ یا سرویس سازگار با پروتکل MySQL با TLS و دسترسی از Vercel ایجاد کن. برای جلوگیری از هزینه اضافه، پلن رایگان را انتخاب و محدودیت منابع/ترافیک را بررسی کن.

مشخصات اتصال را **فقط در Vercel Environment Variables** وارد کن؛ نه در GitHub یا چت:

| متغیر | مقدار | محیط |
|---|---|---|
| `DATABASE_URL` | `mysql://USER:PASSWORD@HOST:3306/DB_NAME` (رمز URL-encode شود) | Production + Preview |
| `SITE_URL` | `https://cinesense.aminvost.ir` | Production + Preview |
| `CRON_SECRET` | رشته تصادفی با حداقل ۳۲ بایت | Production |
| `RESEND_API_KEY` | کلید خصوصی Resend با دامنه تأییدشده | Production + Preview |
| `AUTH_EMAIL_FROM` | آدرس تأییدشده مانند `CineSense <no-reply@cinesense.aminvost.ir>` | Production + Preview |

TLS به‌صورت پیش‌فرض اجباری و اعتبار گواهی کنترل می‌شود. متغیر `DATABASE_TLS_DISABLED` فقط برای تست محلی MySQL در محیط CI استفاده می‌شود؛ **روی Production هرگز true نشود**.

## ۲. اجرای جداول
فایل `db/schema.sql` را **یک بار** در SQL editor سرویس دیتابیس اجرا کن، یا در سیستم توسعه با ارتباط امن:

```bash
cd movie-scraper
npm ci
# DATABASE_URL را با روش امن متغیر محیطی در سیستم تنظیم کن
npm run db:migrate
```

با `IF NOT EXISTS` اجرای مجدد، داده‌های قبلی را حذف نمی‌کند. بعد از مهاجرت، Vercel را Redeploy کن تا متغیرهای جدید لود شوند.

## ۳. ایمیل و حساب
برای ثبت‌نام عمومی، دامنه ارسال در Resend تأیید شود؛ DNS را بدون تغییر رکوردهای فعلی سایت/ایمیل تنظیم کن. اطلاعات احراز هویت حتماً با کوکی HttpOnly و TLS منتقل می‌شوند. رمز با scrypt+salt هش می‌شود. ورود فقط بعد از تأیید ایمیل مجاز است؛ لینک تأیید یا بازیابی ۳۰ دقیقه اعتبار دارد. تاریخچه فقط برای صاحب همان حساب قابل دریافت است و کاربر می‌تواند حساب و تاریخچه را حذف کند.

## ۴. کش مشترک و جلوگیری از Fetch تکراری
- هر snapshot با کلید `(tmdb_id, source)` مستقل از کاربر در MySQL نگهداری می‌شود.
- snapshot تا **۲۰ روز پس از دریافت موفق** معتبر است؛ تعداد نظرات ذخیره شده و `hasMore` بررسی می‌شود.
- cache hit هرگز باعث تماس با YouTube یا اجرای Chromium جدید نمی‌شود؛ صرفاً MySQL query مصرف می‌کند.
- درخواست هم‌زمان روی فیلم/منبع یکسان به قفل دیتابیس می‌رود؛ درخواست دوم تا ۱۰ ثانیه منتظر داده آماده می‌ماند و در صورت طولانی‌شدن، پیام retry می‌دهد؛ Chromium دومی شروع نمی‌کند.
- دریافت‌های جدید در ۲۴ ساعت (تقویمی) به‌صورت مشترک محدود می‌شوند: **YouTube: ۴۰، DigiMoviez: ۳۰**، بعلاوه سقف‌های کاربری؛ با هدف محافظت از سهمیه API رایگان.
- شکست دریافت منبع، زمان کش را تمدید نمی‌کند.
- خروجی فقط review text و source metadata عمومی است؛ کد خصوصی و اطلاعات حساب در کش اشتراکی ذخیره نمی‌شود.
- Vercel Cron روزی یک‌بار snapshot و session/token/rate-counter منقضی‌شده را پاک می‌کند. تا وقتی `CRON_SECRET` تنظیم نشده، endpoint نگهداری به‌صورت امن غیرفعال است.
- تابع‌های Vercel همچنان محدودیت زمان و حافظه دارند. این معماری صف دائمی worker ندارد و برای بار بسیار سنگین باید queue واقعی اضافه شود.

## ۵. مدل‌های محلی
مدل‌های زبان فارسی و چندزبانه با `env.useBrowserCache=true` از Cache Storage استفاده می‌کنند. با اجرای اولین تحلیل، مرورگر تلاش می‌کند storage را persistent کند و وضعیت کش را نمایش می‌دهد. این کش **وابسته به مرورگر و دستگاه** است نه حساب کاربری. حذف یا تخلیه کش مرورگر / Private Mode ممکن است دانلود مجدد لازم کند. نتیجه تحلیل AI مرورگر به‌عنوان حقیقت سراسری و قابل‌دستکاری توسط کاربر وارد DB مشترک نمی‌شود.

## ۶. نکات امنیت و هزینه
- در صورت افشای هر رمز، فوراً در سرویس مربوطه Rotate کن.
- محدودیت‌های rate و قفل دیتابیس، از مصرف بیش‌ازحد منابع می‌کاهند اما جای مانیتورینگ و محدودیت مالی/سهمیه در Vercel، YouTube و سرویس دیتابیس را نمی‌گیرند.
- ذخیره نظرات منابع ثالث باید مطابق شرایط نگهداری، حذف، حذف نظر توسط نویسنده و حقوق داده آن سرویس باشد. برای عرضه عمومی و تجاری بررسی حقوقی لازم است.
- هیچ کلید خصوصی یا رمز عبوری نباید در `NEXT_PUBLIC_*`، HTML، چت یا Repository قرار بگیرد.

## تست
```bash
cd movie-scraper
node --test test/*.test.mjs  # بدون تست mysql-integration.mjs
# DATABASE_URL تست روی MySQL مجزا، نه دیتابیس production:
npm run test:db
npm run build
```
CI دارای workflow واقعی با کانتینر MySQL 8 است: `.github/workflows/mysql-integration.yml`.
